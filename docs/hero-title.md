# 首页 hero 标题 — 逐字调位 + 量测网格

> 涉及文件：`src/components/home/Hero.astro`（`.type-line` 的逐字 span、`.ltr` 样式、`<style>` 末尾烘焙的 20 条逐字偏移规则）、`src/scripts/hero-tuner.ts`（**保留但不删**的调音面板，`TUNER_ENABLED` 开关）。
> 只在动首页标题的字距/字位、或要重新调这批偏移时才读。
> 状态：逐字偏移**已定稿并烘焙**（2026-09-19，两轮微调）。面板一度随烘焙一起删掉，用户随后要求恢复——「以后就隐藏起来，不删除了，我觉得有他还很方便」——所以现在**代码常驻、靠 `TUNER_ENABLED` 开关**，当前值 **`false`**：面板与量测网格整页消失，代码一行不少。要再调就把那一行改成 `true`。

## 一、为什么需要逐字调位

`FUNCTIONAL` / `AESTHETICS` 两行是 `--font-display`（Saira Condensed 900）**一整段 `letter-spacing: -2px`** 排出来的，而 condensed 字体的**字对推进量差异极大**（`FU` 紧、`CT` 松）。在 `--text-scale-hero` 的字号下差的不是零点几像素，是屏幕上看得见的一段空白——用户原话「每个字母之间的间隔都不一样，视觉上很糟糕」。**一个统一值不可能拉平**，所以每个字都要能自己走一点。

做法（`Hero.astro`）：两行各自 `split("")` 成 `<span class="ltr" data-line="1|2" data-i="0…9">`，样式只有一句：

```css
.ltr { display: inline-block; transform: translate(var(--lx, 0px), var(--ly, 0px)); }
```

## 二、定稿值（烘焙在 `Hero.astro` 的 `<style>` 里）

`--lx`/`--ly` 由 20 条 `.ltr[data-line][data-i]` 规则给出，顺序即阅读顺序：

```css
.ltr[data-line="1"][data-i="2"] { --lx: -1.5px; --ly: 0px } /* N */
```

| 行 | 逐字 `--lx`（px） |
| --- | --- |
| 1 `FUNCTIONAL` | F 0 · U 0 · N −1.5 · C **−2.5** · T 1 · I 2 · O 1.5 · N 1 · A 3 · L 4.5 |
| 2 `AESTHETICS` | A 3 · E 5 · S 5.5 · T 6.5 · H **7.75** · E 6 · T **8.5** · I 9.5 · C **8.5** · S 9.5 |

**全部 `--ly: 0px`**（用户只调了水平间距）。趋势是越往右越往外让（condensed 900 的字对在右端最挤），但个别字母会回落（两组 `E`、第二个 `C`）——这是**逐字量出来的，不是一条曲线拟合出来的**。

⚠️ **第二轮微调（同一天）**：line 1 `C` −1.5 → **−2.5**；line 2 `H` 8 → **7.75**、`T`(i=6) 8 → **8.5**、`C`(i=8) 9.5 → **8.5**。`H` 这个值来自用户说明——「他不是 8，而是介于 7.5-8 之间位置最理想」——而**滑杆当时是以 0.5 为步进的，手调根本调不出 7.75**（「我每次调整数值只能在 0.5 之间变化，无法更精细的调整」），所以那次 COPY 块里 `H` 仍写着 `8px`。现在 `STEP = 0.25`，这类值下次能直接调出来。

实测（1700×900，CDP 读 `getComputedStyle`）：两行 20 个 span 的 `matrix` 位移与上表逐字一致 ✓；相邻字盒间隙（px）`0 / −1.5 / −1 / 3.5 / 1 / −0.5 / −0.5 / 2 / 1.5 / 2 / 0.5 / 1 / 1.25 / −1.75 / 2.5 / 1 / −1 / 1`——负值来自字对本身的挤压（字盒含两侧边距，画面上并不叠笔）。

定稿时面板上那套量测网格的参数（**仅作记录**）：`density 11 · cell 46x34.5 · gap 0 → pitch 46x34.5, fine 4.18x3.14, coarse 230x172.5`。同一行也抄在 `Hero.astro` 的注释里，并**就是面板的 `GRID_DEFAULTS`**——所以打开面板会复现当初量这批偏移时的那张网格。

⚠️ **不要用 `textContent` 重建这两行**：span 上的 `data-astro-cid-*` 是 Astro 作用域选择器命中的唯一凭据，而打字机是靠 `innerHTML` 写回原文才把它们带回来的。改成 `textContent` 会让 `.ltr` 与那 20 条偏移规则同时静默失效（标题退回整段文本的样子）。

⚠️ **面板不能再往没被调过的字母上写 0。** 面板刚做出来时默认值是全 0，`applyLetter()` 无条件写内联 `--lx: 0px`；现在基线是一整张非零表，内联 0 会**盖掉**烘焙值——任何没有 localStorage 的浏览器一打开首页就是「焊接好的字母被打散」。所以 `applyLetter()` 的语义是：**有覆写才写，没有就 `removeProperty` 交还给样式表**（实测：新档打开时 20 个 span 的 `style` 全空、位移等于烘焙值 ✓）。

## 三、面板（`hero-tuner.ts`）——保留、默认关闭

- 开关是文件顶部的 `const TUNER_ENABLED = true/false;`（**当前 `false`**），`initHeroTuner()` 首行早退。**`false` 时整套工具消失**：chip、面板、量测网格、十字准线、坐标读数、四个监听器一个都不建，页面完全由样式表与烘焙值驱动（照 `shelf-tuner.ts` 的惯例）。
- **`TUNER_ENABLED = true`**：底部居中的 chip「tune hero letters」（**反引号 `` ` ``** 也能开关，输入框内不抢键）、右侧可拖动的磨砂面板。每个字母两根滑杆（X / Y，±30px、**步进 0.25**），旁边是数值读数；**COPY** 输出可直接粘贴的逐字 CSS（头部带一行网格注释）；**RESET** 把字母与网格**一起**复位到**发版值**（字母＝烘焙表，网格＝`GRID_DEFAULTS`），半复位读起来像 bug。
- **滑杆、读数、COPY 都读「有效值」** `effective(l) = 本地覆写 ?? 烘焙值`——所以面板一打开就停在发版值上，按下 COPY 直接拿到完整可粘贴的 20 行（未调过的字母打印的是它的烘焙值，不是 0）。
- 持久化两个键：`localStorage["rrsuika-hero-letters-v1"]`（字母，**只存被调过的增量**）、`localStorage["rrsuika-hero-grid-v1"]`（网格）。都不进仓库。

⚠️ **三个坑，都踩过**：

1. **打字机在面板启动时还没有字母 span。** `Hero.astro` 的打字机会对每条 `.type-line` 先 `innerHTML = ""`，打完才写回原文，所以启动时必须**轮询**等它。⚠️ 而且它是**一行一行**写回的——只判「有 span」会拿到**只有第一行的 10 个字母**（20 根滑杆），必须等到 `[data-line="2"]` 出现（实测修好后 20 字母 / 40 滑杆 ✓）。
2. **`STYLE` 是模板字符串，注释里不能出现反引号。** 写 `` `pointer-events: none` `` 这种行内代码会把整个文件从那里截断（`astro check` 报一堆 `',' expected`）。CSS 注释里一律用普通文字。
3. **别用 `const grid` 去接网格元素。** 模块级已经有一个 `grid`（网格参数状态），`build()` 里再声明一个同名局部常量会在整个函数作用域把它拖进 TDZ：前面读 `grid.density` 的那几行会直接抛 `Cannot access 'grid' before initialization`。元素叫 `gridEl`。

## 四、量测网格的四个变量

面板打开时同时出现三样东西（关面板三样一起消失），全部 `pointer-events: none`、`z-index` 低于面板：

1. **6 层网格**：两个轴 × 三个层级，**用强调色**画（纯白网格在浅色主题上会消失）。
2. **十字准线**：贴在 hero `h1` 盒子的**左边缘**与**垂直中心**（实测 227px / 255px）——这样偏移量是对着一个真实的东西读的，不是对着视口。
3. **坐标读数**：跟着指针走（实测 `600 , 400`）。

2026-09-19 用户要「添加变量，调整网格的密度，格子的宽度，格子的大小，间距」，于是网格的间距不再写死：

| 滑杆 | 范围 | 含义 |
| --- | --- | --- |
| 密度 DENSITY | 1–16，步 1 | 一个格子里切几根细线 |
| 格子宽 CELL W | 2–240，步 0.5 | 格子的宽（px） |
| 格子高 CELL H | 2–240，步 0.5 | 格子的高（px） |
| 间距 GAP | 0–48，步 0.5 | 格子与格子之间的空隙 |

**推导只有三行**（`applyGrid()`）：`pitch = cell + gap`；`fine = pitch / density`；`coarse = pitch × 5`。算出来的六个间距写回 `.ht-grid` 的内联自定义属性（`--ht-fine-x/y`、`--ht-mid-x/y`、`--ht-coarse-x/y`），六个 `repeating-linear-gradient` 图层消费它们；滑杆下面再印一行实际像素（`fine … · cell … · coarse …`），**与 COPY 头部那行同一个格式**——因为「46 + 0 间距、密度 11」才是有用的那一半测量，屏幕上那几根线不是。

⚠️ `sanitise()` 必须夹住：**`density` 可以是 1、也可能从旧数据里读到小数**，一旦算出 0 或 NaN 的间距，浏览器会**整层丢掉**那个 `repeating-linear-gradient`——网格少一层是静默的，不会报错。

**实测**（1700×900，CDP）：

- 面板打开（未动滑杆）：内联属性 `--ht-fine-x: 4.18px / --ht-fine-y: 3.14px / --ht-mid-x: 46px / --ht-mid-y: 34.5px / --ht-coarse-x: 230px / --ht-coarse-y: 172.5px` ✓ 6 个图层全部存在 ✓ 读数行 `fine 4.18 / 3.14 · cell 46 / 34.5 · coarse 230 / 172.5`（与烘焙注释逐字一致）✓ 四个滑杆初值 `11 / 46 / 34.5 / 0` ✓。
- 把 LINE 1 的 `L` 的 X 滑杆推到 12：只有那个字母拿到内联 `--lx: 12px`（其余 19 个仍是 `baked`）✓ 位移 `matrix(1, 0, 0, 1, 12, 0)` ✓ 存储写成 `{"1:9":{"x":12,"y":0}}`（增量）✓。
- 按 RESET：内联全部清空、20 个字母回到烘焙值 ✓ 存储回到 `{}`、网格回到 `GRID_DEFAULTS` ✓。

**烘焙后复验**（面板已关的那一版，1700×900，CDP，清空 localStorage）：20 个 span 的位移逐字等于第二节的表 ✓、`style` 全空（无内联残留）✓、`document.styleSheets` 里 20 条 `.ltr[data-line]` 规则全部命中 ✓、**烘焙块之后**的规则也还在（`.type-line.typing::after`、`.btn-icon`、`.telemetry-strip`、`.crt-fade-bot`、`.coords` 逐个查到）✓——最后这条就是「`<style>` 里多一个 `{` 会静默丢掉后面所有规则」的复验，改完 `<style>` 必须做。工具侧的残留全为 0：chip / 面板 / 网格 / 准线 / 坐标读数都是 0 个节点，`#hero-tuner-style` 不存在 ✓。

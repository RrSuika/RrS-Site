1. **Astro + 零集成**：站点以静态内容为主、无重交互，追求构建简单与极致静态性能；不需要框架岛屿。所有交互用少量原生 JS 内联实现。
2. **单一 Content Collection（entries）+ 多 `type` 字段**：全部内容共用一份 schema 和一套动态路由，新增条目零代码。`type` 枚举 `projects/lab/note/art` 按内容性质分类（作品集/实验记录/学习笔记/艺术），**不是** `work`;不要按老文档或直觉改名。`gallery` 是字段不是 type。
3. **手动 i18n / 每语言独立页面文件**：en 与 zh 页面是**两套独立文件**而非共享模板，因为 about/art 页两语言差异极大（脚本、动画参数、样式覆盖都不同）。代价是双维护;这是被接受的设计，不是缺陷（新静态页必须建 zh 镜像）。
4. **双动态路由分工**（`[type]/[...slug]` 管 en、`[lang]/[type]/[slug]` 管 zh 且 lang 硬编码 "zh"）：让 en 保持无前缀、zh 有 `/zh` 前缀，两个文件对称可读。`[...slug]` rest 是前瞻设计（当前只用到单段）。
5. **`/note/{slug}` 单数 vs `/notes` 列表**：历史上出现过分叉的映射生成 `/notes/{slug}` 产生 404；此后 `routes.ts` 被定为链接生成的单一事实来源（见 §10 的残留偏差）。
6. **首页精选用硬编码 `featuredKeys`**：用户偏好人工策展（"featured" 字段反而只作声明）；改精选要动两个首页文件的前端代码。
7. **SYS.LOG 排除 art**：art 无详情页，排除避免首页链接到 404;任何"最新内容"类列表都应遵守此过滤。
8. **设计系统清理时的 FIDELITY POLICY**：token 值 1:1 复制原样式，宁可保留字面量也不"统一"颜色；旧调色板（`#ff5f1f` 警告橙、三原色点、`#00703c`/`#145a28` 旧绿）是用户选择保留的原始视觉，**不要重着色**（CLAUDE.md 同款规则）。
9. **Hero 终端临时隐藏（§14）**：用户评估无终端首页是否更清爽的实验；元素完好，恢复=删一条 CSS 规则。
10. **art 页面冻结**：用户决定不再改动 art 列表页、ArtGallery、gallery schema 字段（只允许改 SEO frontmatter）。相关代码视为历史冻结区。
11. **滚动条完全隐藏**：原始设计保留的用户偏好（牺牲可发现性，用户知情）。
12. **主题默认暗色**：不跟随系统偏好，首次访问一律 dark（防闪烁守卫 + localStorage）。

14. **全站 JSON-LD**：WebSite（每页）+ Person（about）+ TechArticle（详情）为 SEO 富结果服务；日期必须完整 ISO-8601 带时区（schema.org 要求）。
15. **og-card.png 手工生成**：分享卡视觉（终端风格 + 三色条 + 中英标语）由脚本硬编码 SVG 渲染，无构建步骤;改分享卡要改脚本并手动重跑。
16. **全站 URL 统一尾斜杠（2026-08-31）**：`astro.config.mjs` 设 `trailingSlash: "always"`（canonical/hreflang/og:url 自动带尾斜杠），`getLocalizedPath`/`buildEntryUrl`/`sitemap.xml.ts` 均输出尾斜杠，硬编码链接（404 页按钮、JSON-LD `url`）也带尾斜杠。原因：Cloudflare Pages 对目录型页面把不带斜杠的请求 308 重定向到带斜杠版本；默认 `"ignore"` 会让每个页面的 canonical 指向重定向 URL，Google Search Console 报"网页会自动重定向"并拖累收录。**新增内部链接必须带尾斜杠**（唯一例外：资源文件与首页 `/`）。
17. **正文图片构建时解析（2026-08-31）**：新增 `src/utils/markdown-resolve-images.ts`（Sätteri raw 节点插件，经 `markdown.processor: satteri({ hastPlugins })` 注册），把正文原始 HTML 中 `<img src="./…">` 重写为 `__ASTRO_IMAGE_` 标记并加入 `localImagePaths`，由 Astro 原生内容图片管线（image-marker + `updateImageReferencesInBody`）在渲染期解析为哈希 webp URL；同时删除了 ProjectDetail 里旧的客户端图片修正（隐藏 div 图片表 + DOMContentLoaded 重写）。原因：浏览器解析 HTML 时先用相对路径发请求，Cloudflare Error Monitoring 报大量详情页图片 404；markdown 语法图片（`![](./x.png)`）本就走原生管线，只缺原始 HTML 图片。**关键坑**：① 插件随 astro.config 打包，配置 bundle 里 `import.meta.glob(eager)` 的图片值没有 astro:assets 处理（`.src` 是 `/src/content/...` 原始路径，生产 404），插件内只能使用 lazy glob 的**键**做存在性检查，绝不解析**值**；② Astro 内容层把渲染结果缓存于 `node_modules/.astro/data-store.json`（仅按文件摘要失效），改动 markdown 管线配置后须删除 `node_modules/.astro` 强制重渲（Cloudflare 从干净环境构建，部署不受影响）。
18. **首页黑洞视频背景层（2026-09-09）**：用户要求首页暗色模式下叠层为「纯黑色背景 → 黑洞视频 → 星空 → 其他元素」，其他页面保持原样。实现方式：视频原样拷贝为 `public/media/blackhole.mp4`（1920×1080/60fps/约 5s/3.1MB，h264 yuv420p，**未转码**），`Layout` 新增 `blackhole` 布尔 prop，为 true 时在 `#starfield-canvas` **之前**插入 `#blackhole-layer`（`position: fixed; inset: 0; z-index: 0; background: #000; overflow: hidden`）内含 `<video autoplay muted loop playsinline preload="auto">`；三者同为 `z-index: 0`，因此**层序完全由 DOM 顺序决定**——若日后移动标记位置，层序会跟着变。只有三个首页传 `blackhole`。light 模式整层 `display: none`（保留复古网格）；`prefers-reduced-motion` 时脚本 `pause()` 只留首帧（不删除层，视觉构图不塌）。**渐入**：JS 立刻给层加 `.bh-fade`（`opacity: 0` + 0.35s 过渡），在视频 `loadeddata`/`canplay` 时加 `.is-ready` 淡入，避免首帧解码期间「闪一下」；无 JS 时 `#blackhole-layer:not(.bh-fade)` 的 `blackholeIn` 动画兜底，另有 1.5s 超时保护防止永久不可见。渐入时长在 global.css §10 的 `#blackhole-layer.bh-fade` 一处改。尺寸/位置用 `--blackhole-*` 自定义属性（x/y/width/height/scale/opacity，定义在 `#blackhole-layer` 内）+ `object-fit` 调节，注释写在 global.css §10。**`--blackhole-y` 线性跟随视口高度**：`calc(122px + 37.8vh)`。用用户现场 HUD 调出的两组真实数据拟合——视口高 562px（1080p 屏）时 59.5% = 334px，视口高 802px（2K 屏）时 53.0% = 425px（两点都在 0.1px 内复现）。**教训**：纯百分比（52%/60%）或按"屏幕分辨率"的假设都靠不住——用户两块屏的实际视口只有 562/802px（Windows 缩放 + 窗口非最大化），百分比会随窗口高度漂移；`clamp(52%, calc(345.6px + 28vh), 60%)` 和 `@media (min-height: 1200px)` 两档方案都因为假设视口≈屏幕分辨率而失效。以后调这个值，用 Layout 里那个 `?bhtune=1` 工具量真实数据。**桌面端限定**：`<video>` 不带 `autoplay`/`src`，改用 `data-src`，脚本只在 `min-width: 769px` 时挂载并播放，手机端既不显示也不下载（CSS 也加了 `@media (min-width: 769px)` 双保险）。**权衡**：`#blackhole-layer` 的纯黑底会盖住 `body::before` 的 hex grid（首页暗色模式下网格不可见），这是层序要求的直接结果；`body::after` 噪点与 `#crt-overlay`/`#tube-vignette` 仍在最上层，保持整机 CRT 质感。
19. **星空每帧开销优化（2026-09-09，配合首页视频）**：`drawStar()` 原先每帧为每颗星新建径向渐变并拼接 4 个 rgba 字符串（500–1200 颗 × 60fps），实测 600 颗星约 3.0ms/帧，抢占主线程导致首页黑洞视频偶发掉帧。改为 `prepareStar()` 在首帧算好 `glow`（原点渐变）、`glowRadius`、`coreRadius`、`flare`、`alphaBase` 缓存到 `star.cache`，绘制时 `ctx.save(); ctx.translate(sx, sy)` 复用同一条渐变，alpha 改由 `globalAlpha` 承担（数学上与旧版逐 stop 乘 alpha 等价），实测降到约 0.9ms/帧，渲染结果不变。**注意**：缓存假设相机固定（`camYaw`/`camPitch` 恒为 0）；若日后恢复相机旋转，必须改为每帧重算或按帧失效。同批还加了：`#blackhole-video { will-change: transform }`（独占合成层）、**视频持续播放**——原先「标签页隐藏 / 切亮色主题就暂停」的省解码逻辑已被用户要求去掉（会引起各种奇怪的停播），改成 2s 看门狗兜底重播（仅桌面端）。

20%），`r < rRing` **完全不绘制**——视频黑洞的纯黑透出，圈内没有任何星星（用户明确要求）。用户要求星**跨层连续**，原「三层各自循环、层内边界回收」是错误行为，已弃——同一颗星自外场边缘出生后沿半径**单调内落**、穿越全部速度分段，途中被吸积盘遮住时继续下落（`diskMaskAlpha` `dr/speed`（fRing = 圈前淡出带宽，不在淡出尾内播种）+ 二分采样——初始帧即稳态密度、无松弛波、无边界缝。`rMid` 两侧速度用**平滑斜坡**过渡（smoothstep，半宽 `rampW` = min(两段跨度)×约 12%，clamp 12–80px）取代速度跳变线；内层段在 `rInner` 处取值恰为 `speedMid`（连续）。**旋进**：内流同时按 `--lens-swirl`（∝ `rRing/r`）顺时针螺旋落入；**吸积盘遮罩**：旋转+压扁的椭圆环（`--lens-disk-inner-w/h`、`--lens-disk-outer-w/h`、`--lens-disk-tilt/dx/dy/feather`，整体上移使下半更小）内的星（按透镜后屏幕半径）完全不画，进入时按 `feather` 淡出、从 `diskInner` 内边界淡入（不再硬切）。**光子带**：黑洞圈外那圈星是**圆形**的（不做切向拉伸，`--lens-stretch` 对它们无效），更小（`--lens-photon-size`，光晕同步缩小）也更亮（`--lens-gap-boost`），宽度 `--lens-photon-band`（×视口高）填满「盘内边→黑洞圈」的窄缝；宽度应小于盘内边界的最小半轴（`--lens-disk-inner-h` − `--lens-r-ring`，默认 0.276−0.25≈0.026），否则圆带会被椭圆遮罩裁成椭圆。**引力透镜近似**：靠近 `rRing` 时 `--lens-bulge` 向外推、`--lens-stretch` 个视频锚定旋钮不再是"每个屏都要手调"的单点值，而是自适应模型的两个校准锚之一——**换屏幕/拖窗口到别的显示器会自动重新对齐**，见决策 21。
21. **引力透镜视口自适应默认值（2026-09-10）**：用户反馈——§10 同一套参数在 2K 屏（视口 1661×802）调好后，把窗口拖到 1080p 屏（视口 1234×562），黑洞圈与中心对不上视频；随后给出他在 1080p 屏手调出的整套最佳参数作校准数据。两档数据严格符合同一缩放律：视频盒 125% + `object-fit: cover`，凡宽高比 ≥16:9（width-bound）的窗口，视频所有特征随**视口宽度 W** 缩放（两组实测互证：rRing px = 200.5@1661 与 149@1234 ≈ 0.1207·W；中心 y = 122 + 0.378·H + δ(W)，δ ≈ 0.028·W）。**实现**（`GravitationalLens.astro` §2a）：7 个视频锚定旋钮——`--lens-cy-vh`、`--lens-r-outer`、`--lens-r-mid`、`--lens-r-inner`、`--lens-r-ring`、`--lens-disk-inner-w/h`——逐特征做两点线性拟合 px = m·W + b（锚 A = §10/FALLBACK 发货基线 = 2K 档；锚 B = 用户 1080p 档；`SCALED` 表内 `a` 引用 FALLBACK 自动跟随），在当前视口下 ÷H 还原成无单位值。`cyVh` 特殊处理：cyPx 两档同为 122（真锚点，不进拟合），`cyVh` 编码的是「视频盒中心线 0.378·H + 随视频宽度走的屏幕偏移 δ」，先拟合 δ 再还原，避免把 H 掺进 W 拟合。**优先级（按来源、不按数值）**：tuner inline 覆盖永远逐字生效（nudge 回基线数值也算显式覆盖）；≠FALLBACK 的手改 §10 块逐字生效（显式冻结）；只有 CSS 恰好等于发货基线才做视口拟合。宽高比 <16:9（height-bound）或 W/H 未定（初始化时序：wire-up 的 readCfg 先于 measure）时保持原基线。**重刷时机**：`measure()` 量完 W/H 后重读 `readCfg()`（启动与 resize 都走它——把窗口拖到另一块屏即自动重拟合，无需刷新）。**HUD/COPY/nudge 一致**：`currentVal` 全部改走 `effectiveVal`（同一拟合路径），面板数值即实际渲染值；COPY 输出若含自动拟合值会加 ⚠ 注释——粘贴的块是**静态快照**，重新基线化必须 global.css §10 与组件内 FALLBACK/SCALED **两处同步改**。**经验**：视频锚定特征按视口宽缩放、且只有两点标定，跨屏只能靠线性外推（与决策 18 `--blackhole-y` 的教训同源：永远不要假设视口等于屏幕分辨率）。

22. **`backdrop-filter` 前缀对会被构建期压缩器合并（2026-09-10）**：用户报「localhost 卡片有毛玻璃，生产站没有」。先排除部署问题——生产 HTML 引用的 CSS 与本地 `dist` **逐字节一致**（同名 hash 文件，5148 bytes），所以不是缓存或部署滞后。真因在压缩器：Vite 8 用 **lightningcss**（`npm ls lightningcss` 可见，astro@7.1.6 的传递依赖；项目无 browserslist 字段）压缩 CSS，它把 `-webkit-backdrop-filter` 当成 `backdrop-filter` 的**别名**，同一条规则里成对出现就合并、**保留最后一条**。`ProjectCard.astro` 原本先写无前缀、后写 `-webkit-` → 产物只剩 `-webkit-backdrop-filter:blur(20px)saturate(160%)`。而 **Chrome/Edge/Firefox 根本不认带前缀的那个**（用 headless Chrome 152 做了对照渲染：只有无前缀的方块背景糊掉，只有前缀的方块和空白对照一样清晰），只有 Safari ≤17 认——于是生产站（Blink 系浏览器）完全没有毛玻璃，dev server 不做压缩、两条声明都在，本地一切正常。**修法**：无前缀那条留在 `.card` 规则里，Safari 的 `-webkit-` 兜底挪到紧跟 `.card` 之后的独立 `@supports (-webkit-backdrop-filter: blur(1px)) { .card { … } }`——一条规则里只有一个声明，压缩器无从合并；已验证产物里两条并存、`@supports` 包装保留（`@supports ((-webkit-backdrop-filter:blur(1px))){…}`）。**教训**：① 「dev 正常、生产失效」的纯 CSS 问题，第一嫌疑是压缩器而不是部署——先比对生产与本地 `dist` 的产物字节；② 任何「前缀 + 无前缀」成对的属性（`backdrop-filter`、`mask`、`user-select`、`text-size-adjust` …）都别写进同一条规则；③ 查这类问题时别用 `grep -c`（压低后的 CSS 只有一行，计数恒为 1，会误判），要用 `grep -o … | wc -l` 或正则 `Matches().Count` 数出现次数。`GravitationalLens.astro` 调参 HUD 里的同款成对写法躺在一个 JS 模板字符串里、不经压缩器，暂时安全——若哪天把它挪进 `<style>`，必须按同样方式拆开。

23. **主题切换是「整页拷贝的圆圈波」，不是填色圆（2026-09-18 v1.23 定稿，取代 v1.19–v1.20 的填色方案）**：用户先要「去掉闪一下 + 频繁点击产生黑白水波纹」，v1.19/v1.20 用「填充目标主题色的圆」做到后发现**这个方案本身是错的**——圆里是一块纯色，会把所有文字和卡片盖住，用户原话「圆会覆盖整个画面，画面黑屏，然后新界面突然从暗部里浮现…圆和之后的浮现很割裂」。定稿改成：每次点击往 `.theme-stack` 叠一份**整页拷贝**（`clip-path` 从半径 0 长到最远角），圆里是**新主题的真实像素**，最后一份盖满视口时所有拷贝在同一帧撤掉，视觉上什么都不变。实现 `src/scripts/theme-transition.ts` + `global.css §15`（入口 `toggleThemeWithReveal(origin?)`，由 `Navbar` 的 `window.__toggleTheme(event)` 转发指针坐标）。**六条不变量，每条都有实测依据**：① **不能用 View Transition 拿快照**（虽然它给的正是真像素）：同一时刻只能有一个 transition，揭示期间的点击会被丢掉、按钮在动画期间是死的——用户报的就是这个；拷贝没有这个限制，N 次点击就是 N 个同时生长的圆、主题交替 ✓。② **拷贝要一个「根不是它」的主题**：项目里所有浅色规则都是 `:root[data-theme="light"] …`，而 `:root` 只匹配 `<html>`、和拷贝挂在谁下面无关，于是**深色拷贝会被当前浅色根的主题规则命中**（实测：深色拷贝里的书架面板变成 `rgb(206,203,198)` 的浅色，全帧平均 |Δ| **107**）。两处一起解决：`buildScope()` 在运行时把**所有以 `:root` 开头的规则**（**包括裸 `:root` 那一块——深色 token 就在那里，项目里根本没有 `:root[data-theme="dark"]`**）改写成 `.theme-scope…` 塞进一张 `<style>`，拷贝带这个 class；同时一轮连点期间把根**停在 `NEUTRAL_THEME`（dark，唯一没有属性专属规则的主题）**，连点结束后再落到目标主题。修好后同一对照是 |Δ| **1.0–2.0**（页面实测 1.95，面板+主角区 2.04）。③ **落地那一帧必须关掉过渡**：`body` 自己就有 400ms 的 background/color 过渡，拷贝撤掉之后再跑这段过渡，就是「从旧主题淡入新主题」——又变回用户骂的那个「浮现」。`applyInstant()` 给 `html` 加 `.theme-land`（`transition: none !important`）→ 换主题 → 强刷一次 recalc → 摘 class。实测落地帧 `body` 背景已是 `rgb(240,235,224)`、在飞的过渡 **0** 个、与纯浅色渲染的 |Δ| **0.09**。④ **不要在拷贝里 pause 动画**：拷贝是插入时才启动动画的，`animation-play-state: paused` 会把它冻在**第 0 帧**（入场动画的「之前」状态——书架磁带整片透明，实测 |Δ| **37**），`animation-delay: -3600s` 更糟（**106**，正好落在某个无限光晕最亮的一帧）；什么都不动才是对的（**2.8**，只剩几个 idle 动画的相位差），书架入场是 JS 驱动的、拷贝里没有可重播的入场。⑤ **拷贝不是 backdrop root**：拷贝里 `.shelf-panel`/`.card` 的 `backdrop-filter` 会去采样**拷贝后面**的页面，所以 `.theme-ripple` 自己带一个 `backdrop-filter: blur(0px)`（不画任何东西，只做隔离）。⑥ **拷贝要手工补齐克隆补不上的东西**：`canvas` 克隆是空的（按序号 `drawImage` 拷位图）、`video` 克隆会**再开一个解码器**（把当前帧画进 `poster`，一轮连点只做一次、缓存）、静态内容要跟着滚动偏移（`margin-top: -scrollY`，滚动时同步）、**与停放主题相同的拷贝直接不做**（活动文档本身就是那一层，省掉整轮最贵的一次）。**验证方法（本轮全靠它定案）**：解码截图逐像素比对——(a) 拷贝 vs 同主题的实时渲染（|Δ| ≤2 才算「没有肉眼可见差别」，顺带证明 **clone 里的 3D 书架没有被 `clip-path` 压平**）；(b) 揭示中途圆内 vs 新主题、圆外 vs 旧主题（实测圆内 |Δ| 1.26 / 对面 204）；(c) 在画面上撒 11×7 个采样点，每个点都必须落在「旧主题」或「新主题」之一上（77/77，证明**任何一帧都不是一块纯色**）；(d) 轮询到拷贝清空的那一刻读 `getComputedStyle(body).backgroundColor` 与 `document.getAnimations()`（抓落地帧）。⚠️ 测这些**永远不要 `a.cancel()`** 圆的动画：burst 靠 `finished` 收尾，取消会让它卡住（1.6s 的兜底计时器才会救回来）。**已知代价**：插入一份拷贝约等于一个长帧（`cloneNode`+插入本身只要 1.3–3ms，长的是浏览器给 ~500 个节点做 layout+paint：headless ANGLE 下最差帧 50–120ms，而同机 idle 帧本来就要 33ms），平均帧时间不受影响（+1ms），所以单次切换是顺的、快速连点每次点击各付一个顿帧。手机/`prefers-reduced-motion`/scope 构建失败一律退回瞬切。**追加（2026-09-19，v1.47）：这个圆的「快慢」由曲线决定，不由时长决定，而且要按面积判。** 用户报「覆盖的速度太快了，肉眼看就像好几帧里面快速的进行了一次覆盖」，问要不要「补帧」——**没有帧可补**，圆是 WAAPI 的 `clip-path` 补间、每帧按墙钟时间算半径，本来就帧率无关。真因是旧 `EASING = cubic-bezier(0.22,
